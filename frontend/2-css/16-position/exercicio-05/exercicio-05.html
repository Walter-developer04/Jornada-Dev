position: static

O padrão — fluxo normal, sem surpresas

Todo elemento HTML é static por padrão. Ele não aceita top, right, bottom nem left. Simplesmente segue o fluxo do documento — onde o browser decidir que ele fica, ele fica.

Static ignora top e left

position: static
top: 30px
left: 30px
(ignorados)

Valores declarados, mas completamente ignorados.

vs
position: relative
top: 30px
left: 30px
(funcionou!)

Mesmo código, mas com relative — o offset funciona.

O fluxo normal — o que static garante

bloco 1 — div com display: block
bloco 2 — ocupa a linha inteira, vai embaixo do anterior
bloco 3 — sem nenhum position declarado. Static puro.

Sem position declarado. Os blocos se empilham naturalmente de cima pra baixo — esse é o comportamento do fluxo normal.

Quando você realmente escreveria position: static?

Quase nunca. static é o padrão de todo elemento HTML — você não precisa escrever pra ativar. Ele simplesmente já está lá.

O único caso em que faz sentido declarar explicitamente é pra resetar um position herdado. Por exemplo: uma biblioteca de CSS define .modal { position: fixed }, mas você quer um modal que não seja fixed numa tela específica. Aí você escreve position: static pra sobrescrever.

Resumo: você não escreve position: static — você remove outro position com ele.
